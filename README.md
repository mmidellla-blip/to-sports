# KBL 점수 예측기

KBL 두 팀의 **전반·최종 점수**를 예측하고, 그 점수를 **농구토토 득점대**와 **승패·언더오버 확률**로 바꿔 보여주는 프로그램이에요.

```
python predict.py --home 원주DB --away 창원LG
```

> 이 프로그램은 돈을 버는 도구가 아니라, 예측하고 검증하며 데이터 분석 실력을 키우는 도구예요.
> 현재 백테스트 평균 오차는 약 8.7점(이번 시즌 8경기)이에요.

## 빠른 시작

```
python predict.py --home 원주DB --away 창원LG --total 173.5 --hcp -3.5
```

출력 예시:

```
=== 원주DB (홈) vs 창원LG (원정) ===
예상 점수
  전반: 원주DB 39.6  vs  창원LG 39.4
  최종: 원주DB 82.6  vs  창원LG 82.1

예상 득점대
  전반: 원주DB 40~44 / 창원LG 35~39
  최종: 원주DB 80~89 / 창원LG 80~89

다른 게임으로 보면 (확률은 가정 기반 근사치)
  승패      : 원주DB 승 52% / 창원LG 승 48%
  예측 합계 : 164.6점
  승5패     : 원주DB 6점차+ 34% / 5점 이내 35% / 창원LG 6점차+ 31%
  핸디캡 -3.5: 승 40% / 패 60%
  언더오버 173.5: 예측 합계 164.6 → 오버 29% / 언더 71%
```

### 결과 읽는 법

| 출력 | 뜻 |
|---|---|
| `[상대전적]` | 맞대결 기록을 몇 % 섞었는지, 섞기 전 점수 |
| `[리그 득점 환경]` | 이번 시즌 리그 득점이 지난 시즌보다 높아 몇 점 보정했는지 |
| `[팀] 지난시즌 … 이번시즌 …` | 그 팀의 평균 득점·실점이 만들어진 과정 |
| 예상 점수 | 전반(1+2쿼터), 최종(연장 포함) 예측 |
| 예상 득점대 | 예측 점수를 토토 매치 구간으로 바꾼 것 |
| 다른 게임으로 보면 | 승패, 승5패, 핸디캡, 언더오버 확률 |

예측 점수가 구간 경계(예: 39.6, 79.7)에 붙어 있으면 그 칸은 **사실상 반반**이에요.

### 팀 이름

띄어쓰기 없이 `last_season.csv`에 적힌 그대로 써요.

`창원LG` `안양정관장` `원주DB` `서울SK` `부산KCC` `고양소노` `수원KT` `울산현대모비스` `대구한국가스공사` `서울삼성`

## 옵션

| 옵션 | 하는 일 | 예시 |
|---|---|---|
| `--home` `--away` | 홈팀, 원정팀 (필수) | `--home 원주DB --away 창원LG` |
| `--total` | 언더오버 기준점 → 오버/언더 확률 표시 | `--total 173.5` |
| `--hcp` | 홈팀 핸디캡 → 핸디캡 승/패 확률 표시 | `--hcp -3.5` |
| `--absent` | 결장 선수만큼 그 팀 점수를 뺌 | `--absent "창원LG:아치 굿윈"` |
| `--boost` | 모델이 모르는 정보를 내 판단으로 더하거나 뺌 | `--boost "원주DB:+3"` |
| `--backtest` | 이번 시즌 끝난 경기를 다시 예측해 오차 확인 | `--backtest` |
| `--season` | 백테스트할 시즌 이름 지정 | `--season 2025-26R6` |
| `--data` `--prior` `--h2h` `--players` | 기본 파일 대신 다른 파일 사용 | `--prior prior_r1-5.csv` |

### 언더오버 `--total`

**두 팀 점수 합계**가 기준점보다 적으면 언더, 많으면 오버예요.
기준점은 베트맨이 경기마다 정하는 숫자라 프로그램이 알 수 없어서, 베트맨 화면의 `U/O 173.5`를 직접 넣어줘요.
안 넣어도 **예측 합계**는 항상 나오니, 눈으로 비교해도 돼요.

> 예) DB 85 : LG 80 → 합계 165 → 173.5보다 적으니 **언더**

### 핸디캡 `--hcp`

홈팀 점수에서 그 숫자만큼 **빼고** 승패를 따져요. 베트맨 화면의 `H -3.5`를 넣어요.

> `-3.5` = "홈팀이 4점 차 이상으로 이기나?"
> DB 85 : LG 80 → 81.5 : 80 → **승** / DB 82 : LG 80 → 78.5 : 80 → **패**

### 결장 선수 `--absent`

- 형식: `"팀이름:선수이름"` — 전체를 **따옴표**로 감싸요
- 팀이름은 띄어쓰기 없이, 선수이름은 `players.csv`의 `name` 그대로 (이름 안 띄어쓰기는 그대로)
- 여러 명은 쉼표로: `--absent "원주DB:레이션 해먼즈,창원LG:아셈 마레이"`
- 계산: 선수 경기당 득점 × 50%를 그 팀에서 뺌
- 이번 시즌 3경기 미만인 선수는 지난 시즌 기록을 쓰고, 팀을 옮긴 선수도 이름으로 찾아요

### 수동 보정 `--boost`

영입 효과처럼 모델이 모르는 정보를 점수로 넣어요.
`--boost "원주DB:+3"` → DB 예측 점수에 3점을 더해요. 여러 팀은 쉼표로.

## 데이터 관리

> ⚠️ KBL 기록 API(`api-stats.kbl.or.kr`)는 robots.txt로 자동 수집을 막아두었어요.
> 데이터는 **브라우저로 직접 보고 복사**하는 방식으로만 가져와요. `fetch_kbl.py`로 자동 수집하지 마세요.

### games.csv 형식

```csv
date,season,home,away,home_half,away_half,home_final,away_final
2026-10-04,2026-27,원주DB,고양소노,45,54,95,86
```

- 전반 = 1쿼터 + 2쿼터, 최종 = 연장 포함
- 전반 점수를 모르면 비워둬도 돼요
- 엑셀로 저장하면 인코딩이 깨질 수 있어요 → 메모장/VS Code로 고치거나 "CSV UTF-8"로 저장

### last_season.csv / h2h.csv / players.csv 형식

```csv
team,pts,opp_pts,memo
창원LG,77.1,71.8,KBL 팀기록 정규시즌 54경기
```

```csv
team,opp,season,games,pts,opp_pts,memo
원주DB,창원LG,2025-26,6,71.5,76.3,KBL 팀기록 팀VS 필터
```

```csv
season_code,team,name,games,min,pts,reb,ast,margin
47,창원LG,아셈 마레이,52,29.4,16.4,14.2,5.4,7.6
```

### KBL 사이트에서 가져오기

| 필요한 것 | 화면 | 설정 | 변환 |
|---|---|---|---|
| 시즌 팀 평균 | 기록 → 팀기록 | 시즌 / **정규시즌** / 1차 스탯 / 누적 | `python parse_team_table.py 표.html` |
| 〃 (JSON) | 〃 + F12 Network → `traditional` 요청 → Response | 〃 | `python parse_team_json.py 응답.json --out season_2025-26.csv` |
| 상대전적 | 기록 → 팀기록 | 세부설정 팀 + 팀VS | 아래 계산식으로 `h2h.csv`에 한 줄 |
| 선수 기록 | 기록 → 선수기록 | 세부설정 팀 선택 | `python parse_players_json.py db.json lg.json --out players.csv` |
| 경기 결과 | 경기 → 일정/결과 | 날짜, 경기 클릭 | `games.csv`에 직접 입력 |

- HTML: F12 → Elements → `<div class="contents">` 우클릭 → Copy outerHTML
- JSON: F12 → Network → 해당 요청 → Response 복사
- 시즌 코드: `49` = 2026-27, `47` = 2025-26, `45` = 2024-25, `43` = 2023-24
- 경기 수가 팀마다 다르면(54, 66, 68…) 플레이오프가 섞인 것 → 정규시즌으로 다시

**실점 계산**: 표의 `+/-`(margin)는 코트 위 5명의 합이라 5로 나눠요.

```
경기당 실점 = (총득점 − (+/-) ÷ 5) ÷ 경기수
```

## 계산 방식

예측은 8단계를 차례로 거쳐요. 숫자는 2026-10-08 원주DB(홈) vs 창원LG(원정) 실제 계산값이에요.

### 1. 평균 회귀 — 지난 시즌 기록을 리그 평균 쪽으로 당기기

3시즌 분석 결과, 팀 **득점**의 개성은 다음 시즌에 거의 이어지지 않고(유지율 ≈ 0), **실점**은 약 70% 이어졌어요.

```
보정 득점 = 리그평균 + 0.3 × (팀 득점 − 리그평균)
보정 실점 = 리그평균 + 0.7 × (팀 실점 − 리그평균)
```

| 팀 | 득점 → 보정 | 실점 → 보정 |
|---|---|---|
| 원주DB | 80.2 → 78.7 | 79.9 → 79.4 |
| 창원LG | 77.1 → 77.8 | 71.8 → 73.7 |

### 2. 지난 시즌 + 이번 시즌 섞기

```
이번 시즌 비중 = n ÷ (n + 5)     (n = 이번 시즌 경기 수)
```

| 팀 | 이번 시즌 | 비중 | 득점 | 실점 |
|---|---|---|---|---|
| 원주DB | 1경기 (95 / 86) | 17% | 81.4 | 80.5 |
| 창원LG | 2경기 (87.5 / 82.5) | 29% | 80.6 | 76.2 |

### 3. 창과 방패 + 홈 이점

```
홈팀 점수   = (홈팀 득점 + 원정팀 실점) ÷ 2 + 1.5
원정팀 점수 = (원정팀 득점 + 홈팀 실점) ÷ 2 − 1.5
```

- 원주DB: (81.4 + 76.2) ÷ 2 + 1.5 = **80.3**
- 창원LG: (80.6 + 80.5) ÷ 2 − 1.5 = **79.0**

### 4. 상대전적 25%

지난 시즌 맞대결 평균(DB 71.5, LG 76.3)에 홈 이점을 붙여 25% 섞어요.

- 원주DB: 80.3 × 0.75 + 73.0 × 0.25 = **78.5**
- 창원LG: 79.0 × 0.75 + 74.8 × 0.25 = **78.0**

### 5. 리그 득점 환경 보정

이번 시즌 팀당 평균 84.8점 vs 지난 시즌 78.1점 → 차이 6.7점 × 8 ÷ (8 + 5) = **+4.1점** (양 팀)

- 원주DB **82.6**, 창원LG **82.1**

### 6. 수동 보정·결장 (옵션 사용 시)

- `--boost "팀:+N"` → N점 더함
- `--absent "팀:선수"` → 선수 경기당 득점 × 0.5 뺌 (예: 해먼즈 20.8 → DB −10.4)

### 7. 전반 점수와 득점대

전반 기록이 3경기 이상이면 팀 전반 비율, 아니면 48%.

- DB 82.6 × 0.48 = 39.6 → 40 → **40~44**
- LG 82.1 × 0.48 = 39.4 → 39 → **35~39**
- 최종 82.6, 82.1 → 둘 다 **80~89**

### 8. 확률

실제 점수가 예측에서 **점수 차 약 12점, 합계 약 16점** 흔들린다고 가정하고 정규분포로 근사해요.

- 점수 차 +0.5 → DB 승 52%
- 합계 164.6 vs 173.5 → 언더 71%

12점·16점은 가정값이라 확률은 참고용이에요. 배당과 비교할 땐 **손익분기 확률 = 1 ÷ 배당**과 견줘요.


### 지난 시즌 백테스트 (데이터 누수 없이)

1. 팀기록에서 2025-26 정규시즌 **라운드별 1~5라운드** 표를 각각 저장
2. `python parse_team_table.py r1.html r2.html r3.html r4.html r5.html --out prior_r1-5.csv`
3. 6라운드 경기 결과를 `games_r6.csv`로 (season 칸 = `2025-26R6`)
4. `python predict.py --data games_r6.csv --prior prior_r1-5.csv --season 2025-26R6 --backtest`

### 과적합 주의

경기가 적을 때 오차에 딱 맞춰 설정을 조이면 다음 경기엔 틀려요.
**20경기 이상 쌓이기 전엔 중간값**을 쓰고, **한 번에 하나씩**만 바꿔요.

## 설정값

`predict.py` 맨 위에서 바꿔요.

| 이름 | 값 | 뜻 | 근거 |
|---|---|---|---|
| `HOME_ADV` | 1.5 | 홈 이점(점) | 일반적 가정 |
| `BLEND_K` | 5 | 이번 시즌을 믿는 속도 | 5경기면 반반 |
| `KEEP_PTS` | 0.3 | 지난 시즌 득점 개성 유지율 | 3시즌 분석 ≈ 0 |
| `KEEP_OPP` | 0.7 | 지난 시즌 실점 개성 유지율 | 3시즌 분석 0.67 |
| `H2H_WEIGHT` | 0.25 | 상대전적 반영 비율 | 6경기라 적게 |
| `LEAGUE_K` | 5 | 리그 득점 변화를 믿는 속도 | 외국인 2명 동시 기용 제도 |
| `HALF_RATIO` | 0.48 | 기본 전반 비율 | 이번 시즌 초반 관찰 |
| `HALF_MIN_GAMES` | 3 | 팀 전반 비율을 쓰는 최소 경기 | 과적합 방지 |
| `ABSENT_FACTOR` | 0.5 | 결장 선수 득점 중 잃는 비율 | 가정 |
| `MARGIN_SD` / `TOTAL_SD` | 12 / 16 | 확률 계산용 흔들림 폭 | 가정 |
| `HALF_BINS` / `FINAL_BINS` | — | 토토 득점대 구간 | 회차마다 베트맨 확인 |

| 증상 | 해결 |
|---|---|
